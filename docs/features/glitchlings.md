# Entities (früher Glitchlings)

**Umbenannt** (Daniel, 17.11.2026: „Ich möchte, dass wir die Glitchlinge umbenennen in Entitys, also das englische Wort für Entitäten. Ich finde, das ist besser.“): in Oberflächen, Spieldaten und Doku heißen sie **Entity / Entities**. Intern bleiben die Kennungen (`glitchlings.json`, Bereich `glitchlings`, Gegenstand `glitchling`, `game/glitchlings.js`, `glitch_face.js` …), damit Spielstände und Verweise halten.

Passive Companions: spezialisierte KIs mit Macken, die es statt Software gibt (design.md › Hacking v3: Entities). Stufe 1 (#047): der Generator.

- **Auftrag** (Daniel, 16.11.2026: „Das Konzept von Software existiert in dieser Welt nicht mehr … spezialisierte KIs, die alle kleine Eigenarten und Macken haben … mit einem starken Deck fangen oder überreden … in Werkbänke einziehen … permanent Cyberware verbessern … einzigartig“; 17.11.2026: „Namen nach dem Schema wie Marble Sting … das hebt sie von Pokémons ab (obwohl sie im Kern genau das ja sein werden) … ein System, auf dessen Basis man diese passiven Companions generieren kann“).
- **Werkstatt** › ENTITIES › Entities (`data/glitchlings.json`, einzeln): **Generator** (je Durchgang 12, Gewicht je Stärke 1–5 Bits 40/30/18/9/3, Fremde Werkbank 35 %), **Namen** (erstes Wort Material/Farbe, zweites Wort Kante/Geräusch/Tat; Name = zwei Wörter, jedes Wort je Durchgang nur einmal), **Begabungen** (Name, Werkbank + Auch als Werkstatt-Funktion, Effekt mit `{n}` = je Bit × Bits, Schlüssel `stat` fürs Spiel: perfect, refund, growth, power, strain, fuel, weaponDamage, battery, rest, value, freshness, sleepHeal), **Macken** (Text + Art: schrullig, Laune, Tageszeit, Wetter, Nachbarn), **Wünsche**, **Wohnorte** (Maschinen in POIs), **Unikate** (handgemacht, „immer“ = in jedem Durchgang: **Amber Slay** (Daniel), Waffenmeister 4 Bits; **Marble Sting**, Chirurg 5 Bits, weiß etwas über die Kinder in den Tanks). Vorschau „Ein Durchgang“ mit Karten (Name, Bits, Begabung, Wohnort, Effekt, Macke, Wunsch) und „Neu würfeln“.
- **Generator** `game/glitchlings.js` (ohne DOM): `generate(D, seed, count)` → Entities `{ id, name, unique, talent, function, also, bits, effect, stat, value, quirk, quirkKind, wish, home, description }`; Unikate „immer“ zuerst, der Rest gewürfelt (gleicher Seed = gleiche Entities, Macken und Wünsche wiederholen sich nicht, solange genug da sind); `effectOf(C, talent, bits, own)`: in der eigenen Werkbank voll, sonst „Fremde Werkbank“ %. Test `test/glitchlings.test.js`.
- **Code-Porträts** (#048, Daniel 17.11.2026: „individuelles, animiertes Code-Porträt, das gleichzeitig das Item-Bild ist“): `game/glitch_face.js` ohne Assets. `faceOf(g)` = Merkmale (Licht aus dem ersten Namenswort, AAP-64; Augen/Mund aus dem zweiten; Form, Glas, Gehäuse aus dem Namen; Zubehör aus `stat` der Begabung, Tabelle `WEARS`; Lämpchen = Bits; Glitch-Art = Macke; Goldrand = Unikat). `renderFace(g, t)` malt ein Bild 40×40 RGBA (12 fps, auch in Node), `drawGlitchFace(ctx, g, t, x, y, size)` auf eine Leinwand, `faceCanvas(g, size)` = Leinwand, die sich bewegt, solange sie auf der Seite ist (fürs Item-Bild im Inventar, sobald Entities Gegenstände sind). In der Werkstatt-Vorschau auf jeder Karte. Neues Zubehör für eine neue Begabung: Eintrag in `WEARS` + Fall in `wear()`.
- **Duell im Spiel** (#052, Daniel 17.11.2026: „als Overlay im Hauptspiel … nahtlos in die UI-UX-Konventionen … alle Hebel, die Türen öffnen, durch Schalter ersetzen, die man erst bedienen kann, wenn man ein Duell ausgetragen hat … Gewinnen ist nur dafür da, die KI zu fangen … KIs in anderen Dingen versteckt … E / Stick ↑ triggert das Duell“):
  - **Brett** `game/stack_view.js` (`StackView`): Kopfzeilen, Pipelines, Walze, `nav(u)` (←/→ Pipeline, ok schickt), `quick()` (Rest sofort, Tests). Die Demo (`stack_ui.js`) und das Spiel nutzen es; CSS `game/duel.css` (beide Seiten laden es).
  - **Overlay** `game/play/glitch_duel_ui.js` (`hud.duel`, angelegt in `scene.setupInventory`, auch ohne Spielstand): Fenster wie die Beute-Bilanz (`.tut` + `.ui-frame`, Titel „Glitch-Duell“, ✕, Hilfezeile mit Tastensymbolen), pausiert das Spiel, Tastatur über eigenes keydown (Pfeile, E/Enter/Leertaste, 1–3, Esc), Controller über `scene.padMenus` → `nav(u)`. Mehrere AI-Cores im Deck: erst wählen. Esc / B / ✕ = aufgeben (zählt als ausgetragen). Ende: Ergebnis + „Weiter“. Kleine Fenster: die Karte schrumpft.
  - **Logik** `game/glitch_world.js`: `cores(save)` (Entities im Deck, sonst `AVA_CORE` ⚠️), `foeFor(D, save, key)` (wer an diesem Ort wohnt: der Satz des Durchgangs, ohne Unikate und Gefangene), `catchGlitchling` (Sieg: ins Deck, sonst Rucksack, sonst Camp-Lager; `save.glitch.caught`).
  - **Schalter** (`poi_level.js`): Kasten mit Bildschirm statt Hebel; solange die KI darin wohnt, flackert er magenta, E/↑ = „Schalter hacken · Glitch-Duell“; nach dem Duell (gewonnen oder verloren) wird er sofort umgelegt und öffnet seine Tür.
  - **Automaten mit KI**: POIs › Marken-Clutter, Spalte „KI“; `level.hosts()` findet sie, E/↑ = „… anzapfen · Glitch-Duell“, einmal je Run. Gesetzt an der Mile 7 Gas & Go (Automaten) und NomadCola-Automaten im Großmarkt, Parkhaus, Sunny Acres, Metro, Raffinerie.
  - Tests `test/glitch_world.test.js`, `tools/glitch_duel_test.mjs`; `poi_test` / `poi_stack_test` spielen das Duell am Schalter mit.
- **Bit-Stapel mobil** (Daniel, 17.11.2026: „eine weitere Version des Spiels als Standalone mobile Variante“, Umfang: nur Layout + Touch): `mobile.html` (Adresse /mobile) mit `game/stack_mobile.js`: Hochformat, schmale Titelzeile mit Siegen/Niederlagen, das Brett von `stack_view.js` (CSS `.mob` in mobile.html: Größen aus Bildschirmbreite und -höhe, schrumpft bei Bedarf), unten Core-Wahl, Gegner und „Neu“. Touch: `confirmTap` – erster Tipp zeigt die Vorschau (Geist-Bit, Feuer, was drüben gelöscht würde), zweiter Tipp schickt. Test `tools/mobile_test.mjs` (iPhone 13, iPhone SE, Pixel 5).
- **Geister-Köpfe** (Daniel 17.11.2026: „mehr wie digitale Geister und weniger wie Fernseher“): Raster `glitch_heads` (32 Köpfe à 64 px, PixelLab). `glitch_face.js`: `loadHeads()` lädt das Raster im Browser einmal (faceCanvas tut das von selbst), `setHeads(cells)` findet in jedem Kopf die schwarze Gesichtsfläche (Füllen von der Mitte), `renderGhost(g, t)` malt 64 × 64: Kopf nach Name, getönt im Licht des Entities, Schweben, Gesicht aus Code in der Fläche, Glitches nach Macke, Goldrand für Unikate. `drawGlitchFace` nimmt den Geist, sobald die Köpfe da sind, sonst (Node, Tests, Kammerjäger) den Bildschirm.
- **Archäologe** (#048): 13. Begabung, Werkbank Warroom, auch Schatzkammer, je Bit 0 (wirkt ohne Stärke), `stat: archaeology`: die Reisekarte zeigt die Fundorte aller einzigartigen Beutestücke (⚠️ zunächst = Merkmal Trophäe). Wirkt erst mit dem Einzug.
- **Entity als Gegenstand** (#048, Daniel 17.11.2026: „Kannst du mir einen Glitchling ins Inventar legen?“): Gegenstand `glitchling` (Kategorie Entity, 2 × 2, stapelt nie); der Eintrag trägt den Entity selbst in `e.g` (`game/inventory.js`: `add(..., { g })`, `addEntry` nimmt ihn mit). Das Bild im Raster und im Tooltip ist sein laufendes Code-Porträt, der Tooltip zeigt Begabung, Bits, Effekt (▲), Macke (▼) und Wunsch. **Geschenk:** `giftGlitchling` in `game/save.js` legt einem Spielstand von vor #048 einmal Amber Slay in den Rucksack (voll → Camp-Lager), gemerkt in `save.gifts`; ein neues Spiel startet ohne (bis das Fangen kommt).
- **Hersteller** (#049, Daniel 17.11.2026: „KIs brauchen einen Hersteller“): Spalte „Hersteller“ bei Begabungen und Unikaten (Verweis auf Lore › Marken); `generate` gibt `brand`, `brandOf(D, g)` findet ihn auch für ältere Entities über die Begabung. Tooltip oben mit dem Markenschild (Logo, Name, Slogan), Werkstatt-Karte mit dem Namen in Markenfarbe, Lore › Marken zeigt „Baut KIs“.
- **Cyberdeck als Fach** (#049, Daniel 17.11.2026: „Man muss sie nicht im Inventar transportieren, wenn man ein Cyberdeck hat“): Waffen der Art Cyberdeck haben **Plätze** (`glitchSlots`; Bastler-Deck 1 „AI-Core“, Daniel 17.11.2026: „ein Einstiegs-Cyberdeck kann nur einen AI Core haben … später zwei oder drei in teuren Decks“). `game/save.js`: `DECK = 'deck'`, `deckSize(D, id)` = [2 × Plätze, 2], `fitDeck(D, inv)` legt das Raster passend zum gehaltenen Deck an (ohne Deck weg, Inhalt wird umgelagert). Im Inventar unter dem Rucksack („Bastler-Deck · 1/2 Glitchlings“), nimmt nur Entities; Aktionen „Ins Cyberdeck“ / „In den Rucksack“; ein Deck mit Entities lässt sich nicht ablegen, ein Tausch klappt nur, wenn sie ins neue passen. **Geschenk:** `giftDeck` gibt einem älteren Spielstand ohne Deck einmal ein Bastler-Deck und zieht seine Entities dort ein (`save.gifts`: `deck_049`).
- **Glitch-Duell** (#050, Daniel 17.11.2026: Kern von OPR Firefight ohne Schlagwörter, wie ein Kartenspiel, Welt pausiert, „wir starten einfach“): Regeln ohne DOM in `game/duel.js`: `statsOf(D, g)` (Präzision nach Bits aus Entities › Duell, Abschirmung nach Hersteller-Stufe, Integrität = Bits + Bonus, Impulse aus den Begabungen: Spalten Einflüstern/Verschränken), `hunterStats(h)` (Entities › Kammerjäger), `newDuel(player, enemy)`, `options(duel, uid)`, `act(duel, uid, action, target, rnd)` → Ereignisse (act, attack, answer, test, steady, out, round, end), `choose(duel, rnd, noise)` = KI, `play()` = ganzes Duell ohne Bild, `preview()` = erwartete Wunden. Aktionen `whisper`, `link` (Ziel antwortet), `calibrate`; angezeigt mit sprechenden Namen (Daniel, 17.11.2026): Sicherer Angriff, Harter Angriff (Gegenschlag), Stabilisieren (`ACTIONS`, `ACTION_SUBS` in `duel.js`); später wieder Einflüstern / Verschränken / Kalibrieren. **Demo** `duel.html` (Adresse /duel, `?foe=wild|hunters&foes=1..3&team=1..3&seed=…&auto&tempo=…`) mit `game/duel_ui.js`: Karten mit Code-Porträt (Kammerjäger: eigenes starres Gesicht, `faceOf({ hunter: true })`), Werte, Integritäts-Balken, Würfel-Tablett, Vorschau am Ziel, „KI spielt für mich“, 1000× simulieren; `window.duelDemo` zum Fernsteuern. Lädt etwas nicht (Datei fehlt, Skript blockiert, Spieldaten leer, nach 20 s nichts da), steht der Fehler auf der Seite (Daniel, 17.11.2026: „/duel lädt nicht“). Tests `test/duel.test.js`, `tools/duel_test.mjs`.
- **Bit-Stapel** (#051, Daniel 17.11.2026: „Knucklebones klingt interessant … abstrakte Demo mit unseren Glitchlingen“): Regeln ohne DOM `game/stack_duel.js` (`newStack`, `place`, `preview`, `colValue`, `total`, `choose` = KI, `play`, `noiseOf`, `favourite` = Lieblingsbit aus dem Namen), Oberfläche `game/stack_ui.js`: je Seite eine KI (`newStack(ki, ki)`; eine Liste gibt wie früher eine je Spalte), Kopfzeile `head()`, drei Pipelines `pipe()`, Walze `reel()` (Streifen mit 14 Bits rollt per CSS `sb-spin` von oben ein; ein Neuzeichnen setzt die Animation mit negativer Verzögerung fort), Wahl „Dein AI-Core“ aus drei Entities des Decks. Wertung `rules`: `dot` Dauerfeuer (Standard, `duel.stackHp` 50; `fireOf`, `colFire`, Überlauf), `hp` Heilen (25; `healOf`) oder `sum` Summe (`?rules=hp|sum`). `/duel` zeigt standardmäßig den Bit-Stapel, `?mode=fight` das ältere Gefecht. Bedienung: Spalte anklicken oder Taste 1–3; Vorschau (Geist-Bit, +Wert, was drüben zerstört wird) per CSS beim Überfahren. Tests `test/stack_duel.test.js`, `tools/duel_test.mjs`.
