# Glitchlings

Passive Companions: spezialisierte KIs mit Macken, die es statt Software gibt (design.md › Hacking v3: Glitchlings). Stufe 1 (#047): der Generator.

- **Auftrag** (Daniel, 16.11.2026: „Das Konzept von Software existiert in dieser Welt nicht mehr … spezialisierte KIs, die alle kleine Eigenarten und Macken haben … mit einem starken Deck fangen oder überreden … in Werkbänke einziehen … permanent Cyberware verbessern … einzigartig“; 17.11.2026: „Namen nach dem Schema wie Marble Sting … das hebt sie von Pokémons ab (obwohl sie im Kern genau das ja sein werden) … ein System, auf dessen Basis man diese passiven Companions generieren kann“).
- **Werkstatt** › GLITCHLINGS › Glitchlings (`data/glitchlings.json`, einzeln): **Generator** (je Durchgang 12, Gewicht je Stärke 1–5 Bits 40/30/18/9/3, Fremde Werkbank 35 %), **Namen** (erstes Wort Material/Farbe, zweites Wort Kante/Geräusch/Tat; Name = zwei Wörter, jedes Wort je Durchgang nur einmal), **Begabungen** (Name, Werkbank + Auch als Werkstatt-Funktion, Effekt mit `{n}` = je Bit × Bits, Schlüssel `stat` fürs Spiel: perfect, refund, growth, power, strain, fuel, weaponDamage, battery, rest, value, freshness, sleepHeal), **Macken** (Text + Art: schrullig, Laune, Tageszeit, Wetter, Nachbarn), **Wünsche**, **Wohnorte** (Maschinen in POIs), **Unikate** (handgemacht, „immer“ = in jedem Durchgang: **Amber Slay** (Daniel), Waffenmeister 4 Bits; **Marble Sting**, Chirurg 5 Bits, weiß etwas über die Kinder in den Tanks). Vorschau „Ein Durchgang“ mit Karten (Name, Bits, Begabung, Wohnort, Effekt, Macke, Wunsch) und „Neu würfeln“.
- **Generator** `game/glitchlings.js` (ohne DOM): `generate(D, seed, count)` → Glitchlings `{ id, name, unique, talent, function, also, bits, effect, stat, value, quirk, quirkKind, wish, home, description }`; Unikate „immer“ zuerst, der Rest gewürfelt (gleicher Seed = gleiche Glitchlings, Macken und Wünsche wiederholen sich nicht, solange genug da sind); `effectOf(C, talent, bits, own)`: in der eigenen Werkbank voll, sonst „Fremde Werkbank“ %. Test `test/glitchlings.test.js`.
- **Code-Porträts** (#048, Daniel 17.11.2026: „individuelles, animiertes Code-Porträt, das gleichzeitig das Item-Bild ist“): `game/glitch_face.js` ohne Assets. `faceOf(g)` = Merkmale (Licht aus dem ersten Namenswort, AAP-64; Augen/Mund aus dem zweiten; Form, Glas, Gehäuse aus dem Namen; Zubehör aus `stat` der Begabung, Tabelle `WEARS`; Lämpchen = Bits; Glitch-Art = Macke; Goldrand = Unikat). `renderFace(g, t)` malt ein Bild 40×40 RGBA (12 fps, auch in Node), `drawGlitchFace(ctx, g, t, x, y, size)` auf eine Leinwand, `faceCanvas(g, size)` = Leinwand, die sich bewegt, solange sie auf der Seite ist (fürs Item-Bild im Inventar, sobald Glitchlings Gegenstände sind). In der Werkstatt-Vorschau auf jeder Karte. Neues Zubehör für eine neue Begabung: Eintrag in `WEARS` + Fall in `wear()`.
- **Archäologe** (#048): 13. Begabung, Werkbank Warroom, auch Schatzkammer, je Bit 0 (wirkt ohne Stärke), `stat: archaeology`: die Reisekarte zeigt die Fundorte aller einzigartigen Beutestücke (⚠️ zunächst = Merkmal Trophäe). Wirkt erst mit dem Einzug.
- **Glitchling als Gegenstand** (#048, Daniel 17.11.2026: „Kannst du mir einen Glitchling ins Inventar legen?“): Gegenstand `glitchling` (Kategorie Glitchling, 2 × 2, stapelt nie); der Eintrag trägt den Glitchling selbst in `e.g` (`game/inventory.js`: `add(..., { g })`, `addEntry` nimmt ihn mit). Das Bild im Raster und im Tooltip ist sein laufendes Code-Porträt, der Tooltip zeigt Begabung, Bits, Effekt (▲), Macke (▼) und Wunsch. **Geschenk:** `giftGlitchling` in `game/save.js` legt einem Spielstand von vor #048 einmal Amber Slay in den Rucksack (voll → Camp-Lager), gemerkt in `save.gifts`; ein neues Spiel startet ohne (bis das Fangen kommt).
- **Hersteller** (#049, Daniel 17.11.2026: „KIs brauchen einen Hersteller“): Spalte „Hersteller“ bei Begabungen und Unikaten (Verweis auf Lore › Marken); `generate` gibt `brand`, `brandOf(D, g)` findet ihn auch für ältere Glitchlings über die Begabung. Tooltip oben mit dem Markenschild (Logo, Name, Slogan), Werkstatt-Karte mit dem Namen in Markenfarbe, Lore › Marken zeigt „Baut KIs“.
- **Cyberdeck als Fach** (#049, Daniel 17.11.2026: „Man muss sie nicht im Inventar transportieren, wenn man ein Cyberdeck hat“): Waffen der Art Cyberdeck haben **Plätze** (`glitchSlots`, Bastler-Deck 2). `game/save.js`: `DECK = 'deck'`, `deckSize(D, id)` = [2 × Plätze, 2], `fitDeck(D, inv)` legt das Raster passend zum gehaltenen Deck an (ohne Deck weg, Inhalt wird umgelagert). Im Inventar unter dem Rucksack („Bastler-Deck · 1/2 Glitchlings“), nimmt nur Glitchlings; Aktionen „Ins Cyberdeck“ / „In den Rucksack“; ein Deck mit Glitchlings lässt sich nicht ablegen, ein Tausch klappt nur, wenn sie ins neue passen. **Geschenk:** `giftDeck` gibt einem älteren Spielstand ohne Deck einmal ein Bastler-Deck und zieht seine Glitchlings dort ein (`save.gifts`: `deck_049`).
- **Glitch-Duell** (#050, Daniel 17.11.2026: Kern von OPR Firefight ohne Schlagwörter, wie ein Kartenspiel, Welt pausiert, „wir starten einfach“): Regeln ohne DOM in `game/duel.js`: `statsOf(D, g)` (Präzision nach Bits aus Glitchlings › Duell, Abschirmung nach Hersteller-Stufe, Integrität = Bits + Bonus, Impulse aus den Begabungen: Spalten Einflüstern/Verschränken), `hunterStats(h)` (Glitchlings › Kammerjäger), `newDuel(player, enemy)`, `options(duel, uid)`, `act(duel, uid, action, target, rnd)` → Ereignisse (act, attack, answer, test, steady, out, round, end), `choose(duel, rnd, noise)` = KI, `play()` = ganzes Duell ohne Bild, `preview()` = erwartete Wunden. Aktionen `whisper` Einflüstern, `link` Verschränken (Ziel antwortet), `calibrate` Kalibrieren. **Demo** `duel.html` (Adresse /duel, `?foe=wild|hunters&foes=1..3&team=1..3&seed=…&auto&tempo=…`) mit `game/duel_ui.js`: Karten mit Code-Porträt (Kammerjäger: eigenes starres Gesicht, `faceOf({ hunter: true })`), Werte, Integritäts-Balken, Würfel-Tablett, Vorschau am Ziel, „KI spielt für mich“, 1000× simulieren; `window.duelDemo` zum Fernsteuern. Tests `test/duel.test.js`, `tools/duel_test.mjs`.
