# Online: Cloudflare, Login, Speichern

Details zu Cloudflare Access, „Speichern = Commit“, Spielstand online, Versionsnummer, verspätete Builds und lokalem Worker. Die Kernregeln stehen in `CLAUDE.md` › Online.

- **Login (Daniel, 07.11.2026): alles hinter Cloudflare Access** (Startseite, Spiel, Werkstatt; E-Mail-Code). Der Worker prüft das JWT für `/api/*` selbst (RS256 gegen `TEAM_DOMAIN/cdn-cgi/access/certs`, `aud` = `POLICY_AUD`, `iss`, `exp`). Ohne `TEAM_DOMAIN`/`POLICY_AUD` antwortet `/api` mit 503, ohne Anmeldung mit 401. `/api/access-info` zeigt nach dem Login Team-Domain und `POLICY_AUD` (Einrichtungshilfe). `GITHUB_TOKEN` (fein eingestellter Schlüssel nur für NomadGirl, Contents lesen/schreiben) ist ein **Geheimnis im Cloudflare-Dashboard**, nie im Repo.
- **Speichern = Commit** (Daniel, 07.11.2026, Port aus NomadTactics ohne Party und Profil): `worker/index.js` beantwortet `/api/*` (`run_worker_first`): `GET /api/session`, `GET /api/files` (alle JSON unter `DATA_DIR` vom aktuellen `main`, mit Blob-sha), `POST /api/commit` `{ base: {datei: sha|null}, changes: [{file, content|null}], force?, name? }` → **ein** Commit über die Git-Data-API, Dateien mit `pretty()`, Nachricht „Werkstatt: … (Name)“. Abweichende Basis → 409 mit `conflicts`; Wettlauf am Ref → bis zu 3× neu; gleicher Inhalt → kein leerer Commit. **Autor:** Name aus der Werkstatt (Klick auf den Namen oben rechts, gemerkt in localStorage `nomadgirl-name`, sonst aus der Login-E-Mail), E-Mail anonym `<name>@werkstatt.nomadgirl.invalid`. Die Login-E-Mail kommt nie ins Repo. Profile (KV) erst später (Daniels Wahl).
- **Werkstatt:** `openCloudStore()` findet den Worker über `/api/session` (sonst `null` → alter Speicher, bei Fehler Hinweis „Nur in diesem Browser“). Speichert **automatisch nach 60 s Ruhe** (`?autosave=N` für Tests) oder sofort mit ⌘S, Status „Ungespeichert · seit …“ / „Gespeichert · …“ (Tooltip mit Commit), Konflikt-Dialog „Jemand war schneller“ (Neu laden | Überschreiben). Kein „Übernimm“ nötig: Ava holt sich vor der Arbeit `git pull`.
- **Spiel live:** `game/play/main.js` lädt online über `cloudFiles()` (`/api/files`) den aktuellen `main`, also sofort nach dem Speichern, ohne auf den Build zu warten (Hilfe-Fenster zeigt den Stand). Ohne Worker: ausgelieferte Dateien plus Browser-Stände.
- **Tests:** `test/cloud.test.js` (Worker gegen falsches GitHub + falsches Access aus `test/fake_cloud.js`), `npm run web:test` (`tools/workshop_cloud_test.mjs`: echte Werkstatt und echtes Spiel im Browser, Autospeichern, ⌘S, Konflikt, Neuladen, Spiel live). Die anderen Browser-Tests ignorieren den 404 von `/api/` am lokalen Server.
- **Spielstand online** (Daniel, 07.11.2026 abends: „online pro Login“): `GET/PUT/DELETE /api/save` im Worker, KV-Namespace `nomadgirl-saves` (Binding `SAVES` in `wrangler.jsonc`, von Ava über die Cloudflare-Verbindung angelegt, die ID ist kein Geheimnis). Schlüssel = SHA-256 der Login-E-Mail, max. 256 KB. Ohne Worker (lokal, Tests) speichert `game/save.js` in localStorage `nomadgirl-save`. **Achtung:** `worker/index.js` darf nur Funktionen exportieren, sonst startet der Worker nicht („Incorrect type for map entry“).
- **Version** (Daniel, 09.11.2026: „versionsnummer im Splashscreen und ingame dezent“, weil online noch der alte Stand lief): `tools/build_web.mjs` schreibt `dist/version.json` (`commit` aus `WORKERS_CI_COMMIT_SHA`, sonst `git rev-parse`, `built`), `game/version.js` (`loadVersion()`) liest sie; Startseite: Fußzeile „v<commit> · TT.MM., hh:mm“, Spiel: Fußleiste unten links (`hud.version`), ohne Build „lokal“. Dazu `dist/_headers` mit `Cache-Control: no-cache`: Browser fragen bei jedem Laden nach (ETag), ein neuer Build ist nach dem Neuladen da. Kommt nach einem Push kein Build (keine Rückmeldung am Commit), hilft ein leerer Commit („Build anstoßen“).
- **Verspätete Builds überholen** (09.11.2026, Daniel: „das Repo fühlt sich alt an“): Cloudflare schaltet den Build live, der **zuletzt fertig** wird, nicht den neuesten Commit. Ein hängender Build von `fd5358e` wurde 20 min nach `0e0a1a8` fertig und hat ihn überschrieben (Symptom: neue Daten, da live von `/api/files`, aber alter Code, keine Versionsnummer). Deshalb nach jedem Push die Abschlusszeiten aller jüngeren Commits vergleichen (`for c in $(git log origin/main -8 --format=%h); do echo "$c $(gh api repos/dna20717/NomadGirl/commits/$c/check-runs --jq '.check_runs[]|(.completed_at//"-")+" "+(.conclusion//.status)')"; done`); ist ein älterer später fertig: leerer Commit „Build anstoßen“. **Build-Schutz** (09.11.2026): `tools/build_web.mjs` fragt auf Workers Builds (nur Branch `main`) zuerst den Kopf von `main` ab (`git ls-remote` auf das öffentliche Repo, sonst GitHub-API ohne Token, je 20 s) und bricht mit Exit 1 ab, wenn er nicht mehr `WORKERS_CI_COMMIT_SHA` ist („Abbruch: dieser Build ist für …“). Ein Nachzügler endet also als **failure** am Commit und geht nicht live; das ist gewollt, solange der neueste Commit `success` hat. Ist GitHub nicht erreichbar, baut er mit Warnung trotzdem. Lokal aus, `NOMADGIRL_HEAD_CHECK=1` erzwingt die Prüfung, `=0` schaltet sie ab. Restlücke: ein Build, der die Prüfung besteht und erst danach hängt, kann weiter überholen, deshalb den Vergleich oben beibehalten.
- **Lokal wie auf Cloudflare:** `npm run build:web`, dann `npx wrangler dev --local --port 8787 --ip 127.0.0.1 --var LOCAL_TEST:1` (Login nur auf localhost ausgelassen).

## Nebenzweige und Vorschau-Builds (14.11.2026)

- **Warum es knallt:** Jeder Push auf einen anderen Zweig als `main` (z. B. den `claude/…`- oder `ccr-…`-Zweig einer Sitzung) startet bei Cloudflare einen Vorschau-Build (`npx wrangler preview`). Ohne `previews`-Block in `wrangler.jsonc` scheitert er und hängt als ❌ am Commit, auch wenn derselbe Commit auf `main` grün ist.
- **Regel:** Nur nach `main` pushen (`git push origin HEAD:main`). Den Sitzungszweig nicht pushen; den lokalen Zweig auf `origin/main` zeigen lassen (`git branch -u origin/main`), dann meldet der Stop-Hook keine „ungepushten“ Commits.
- **Cloudflare (Daniel, einmalig):** dash.cloudflare.com › Workers & Pages › nomadgirl › Settings › **Build** (oder **Builds**) › **Branch control** › Häkchen **„Enable Preview Builds“** raus, bzw. in der neueren Ansicht **Previews Base** › Schalter **„Builds for Preview branches“** aus (Cloudflare-Doku „Build branches“, Stand 08.11.2026). Das Banner „Set up Worker Previews“ nicht anklicken (lässt sich nicht zurückdrehen). Dann baut Cloudflare nur `main`.
- **Alte Zweige aufräumen:** Claude Code darf auf GitHub keine Zweige löschen (Git-Zugang der Sitzung). Daniel löscht sie unter github.com/dna20717/NomadGirl/branches (Reiter „All“, Mülleimer). Vorher prüft Ava, ob alles auf `main` ist (Dateien und Funktionen, nicht nur Commit-Titel: die Geschichte von `main` wurde zusammengefasst). Am 14.11.2026 geprüft und zum Löschen freigegeben: `ccr-437695cc-qev29v` (69f3ee5), `claude/adoring-dirac-zsx1qd` (6783e56), `claude/fervent-einstein-7pkru9` (f910d3c), `claude/modest-heisenberg-bql1lz` (c224efa), `claude/serene-feynman-52g03t` (612d1b0), `claude/sharp-edison-ff2z8n` (e8c8234); nur `tools/_poi_shots.mjs` (Wegwerf-Skript) fehlt auf `main`. ## PixelLab in der Cloud (aus CLAUDE.md, #017)

**Cloud-Umgebung „NomadGirl“** (persönlich, mit dem Repo verknüpft, eingerichtet 10.11.2026): Netzwerk eingeschränkt mit Paketquellen + MCP-Servern + `api.pixellab.ai`; der Schlüssel ist ein **Netzwerk-Geheimnis** für `api.pixellab.ai` (`Authorization: Bearer`), der Proxy setzt ihn selbst ein; `PIXELLAB_API_KEY=vom-proxy-ersetzt` ist nur ein Platzhalter, damit `.mcp.json` einen Header schickt (der Proxy überschreibt ihn). Setup-Skript: Playwright-Verknüpfung in `node_modules/`. Neue Sitzung in der Umgebung „NomadGirl“ starten, `/mcp` zeigt `pixellab`. Schlüssel tauschen: Umgebung › Bearbeiten › Netzwerk-Geheimnisse (oder Ava fragt per sicherem Formular).
